### Загальний протокол виконання для ШІ-агента (System Execution Rules)

Перед запуском будь-якої задачі ШІ-розробник зобов'язаний дотримуватися такого регламенту:

1. **Git-воркфлоу (ізоляція та злиття):**
* Оновити основну гілку розробки: `git checkout develop && git pull origin develop` (на Етапі 0 створити `develop` від `main`).
* Створити гілку задачі за шаблоном: `git checkout -b feat/task-XX-<short-name>`.
* Усі зміни комітити виключно у цю гілку.
* Після проходження **Критеріїв перевірки (Verification)** виконати локальну збірку (`ng build --configuration production`), злити гілку в `develop` (`git checkout develop && git merge --no-ff feat/task-XX-<short-name>`), видалити тимчасову гілку та зафіксувати статус.


2. **Ідемпотентність та перезапуск (Restartability):**
* Усі SQL-міграції мають використовувати конструкції `CREATE TABLE IF NOT EXISTS`, `CREATE OR REPLACE FUNCTION`, `DROP POLICY IF EXISTS ... CREATE POLICY`, щоб повторний запуск скрипта не викликав помилок.
* Усі компоненти Angular пишуться в стилі **Standalone**, із використанням **Angular Signals** (`signal`, `computed`) та суворою типізацією (`strict: true` у `tsconfig.json`), без використання `any`.
* Секретні ключі (`GEMINI_API_KEY`, `ELEVENLABS_API_KEY`, `R2_SECRET_ACCESS_KEY`) ніколи не потрапляють у клієнтський код Angular — вони живуть виключно в секретах **Supabase Edge Functions**.
